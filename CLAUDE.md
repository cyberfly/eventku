## Commands

```bash
pnpm dev          # Start dev server (Vite + TanStack Start)
pnpm build        # Production build
pnpm preview      # Preview production build

pnpm db:generate  # Generate Drizzle migration from schema changes
pnpm db:migrate   # Run pending migrations manually
pnpm db:studio    # Open Drizzle Studio GUI
```

No test runner is configured in this project.

## Environment

Copy `.env.example` to `.env` before first run. Required variables:

- `DB_FILE_NAME` — path to SQLite file (default: `./data/lms.sqlite`)
- `ORGANIZER_EMAIL`, `ORGANIZER_NAME`, `ORGANIZER_PASSWORD` — seed credentials for the organizer account
- `STRIPE_SECRET_KEY` — Stripe secret key for checkout
- `STRIPE_WEBHOOK_SECRET` — Stripe webhook signing secret
- `PUBLIC_BASE_URL` — base URL for Stripe redirect URLs (default: `http://localhost:3000`)

## Architecture

This is a **TanStack Start** (React SSR) app with **Drizzle ORM** on **SQLite** (better-sqlite3) and **Stripe** payments.

### Data layer

- Schema is defined in [src/db/schema.ts](src/db/schema.ts). Tables: `organizers`, `organizer_sessions`, `courses`, `modules`, `lessons`, `enrollments`, `checkout_sessions`, `tickets`, `ticket_messages`.
- `bootstrapDatabase()` in [src/db/index.ts](src/db/index.ts) auto-runs migrations and seed data on first call. All server code uses this instead of importing `db` directly.
- Migrations live in `drizzle/`. Run `db:generate` after schema changes, then `db:migrate` (or let the server bootstrap do it on next start).

### Event/course duality

The database uses "course" terminology (inherited from an LMS), but the public-facing UI calls them "events". The mapping layer lives in [src/lib/events.ts](src/lib/events.ts): `eventExperienceBySlug` is a static map that enriches each course with event-specific metadata (price, venue, city, dates, etc.). [src/server/lms.ts](src/server/lms.ts) merges DB rows with this static data to produce the shapes consumed by routes.

### Server functions

TanStack Start `createServerFn` is used for all server-side logic called from route components. They are defined inline at the top of route files and import from `src/server/` modules lazily (dynamic `import()`) to avoid SSR bundle issues.

### Stripe payment flow

1. User submits the booking form on `/events/$eventSlug` → `createCheckoutSession` server fn
2. [src/server/stripe.ts](src/server/stripe.ts) creates a Stripe Checkout session and inserts a `pending` `checkout_sessions` row
3. User is redirected to Stripe-hosted checkout
4. On success, Stripe fires a webhook to `/api/stripe/webhook`
5. Webhook handler calls `fulfillCheckoutSession`, which inserts an `enrollments` row and marks the session `completed`
6. User lands on `/events/$eventSlug/success?session_id=...` which displays confirmation

### Auth (organizer portal)

Password hashing uses Node's `scryptSync` ([src/lib/organizer-auth.ts](src/lib/organizer-auth.ts)). Sessions are stored in `organizer_sessions` with a random token. The `/organizer` route tree is the admin area for managing courses.

### Routing

File-based routes under `src/routes/`. `src/routeTree.gen.ts` is auto-generated by TanStack Router — do not edit manually. Path alias `@/` maps to `src/`.
